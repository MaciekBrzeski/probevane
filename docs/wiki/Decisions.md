# Decisions (ADR)

Short architecture decision records. Newest first.

## ADR-021 — No package split; logical boundaries only
**Decision:** keep `src/` a monolith. Do NOT extract `probes` (adapters+audit), `vane` (the declarative language), or any other subtree into its own npm workspace package — even though `engine/` (`@facet/*`) proves the workspace pattern works and the module graph already auto-covers new workspaces (`buildGraph` scans root `package.json` workspaces + resolves package-name imports). **Why:** the coupling was priced and none of the candidate cuts is clean. The vane-language *core* (`ast/lex/parse/validate/load/run-command`) is genuinely self-contained (8 out-edges, all in the two integration files `adapter-manifest.ts`/`gen-profiles.ts`), but it is also the only clean one. "Probes" is the repo's tightest **bidirectional cycle** — `adapters ↔ audit` at 8/7 edges each way, with 64 inbound edges to `adapters` from loop(19)/commands(19)/cli(13) — so a probes package ships the cycle intact and rewrites ~64 call sites into `@probevane/probes` specifiers. Every candidate also drags `util` (the universal sink) along. And the payoff — publishing / external reuse — has no consumer yet: the moment a *second* project wants the vane grammar or the probe layer, extract vane-lang first (it's ready), following the facet build-bundling pattern (`tsc` only compiles `src/`, so a sibling package needs its own esbuild step in `build.mjs` + package-specifier imports). Meanwhile the **pyramid model already enforces every boundary at 100/100** — physical packages would add build+dispatch complexity to buy a guarantee we already have. **Revisit trigger:** a real second consumer of the vane language or the probe layer; extract vane-lang only, leave the rest.

## ADR-020 — structure_gate: the pyramid model is an opt-in loop gate
**Decision:** the pyramid structure model (`arch --pyramid`) becomes a `shouldStop` rune (`structure_gate`, opt-in via `--structure` / `ProfileOpts.structure`). It snapshots the target repo's pyramid violations at run start, and on stop-intent blocks if the run INTRODUCED a new one (naming the offending edge + its fix), ratchet-style. **Why:** report-only structural critique tells a human what drifted; a gate stops the loop from drifting in the first place. The pre-run snapshot IS the baseline (no baseline file) — `buildGraph` + `pyramidReport` are seconds, and roles come from the target's `probevane.config` exactly like the CLI. Opt-in, not default: like `mutation`, structural conformance is a project's choice, and a repo with no declared arch roles gets pure-heuristic roles that shouldn't hard-block by surprise.

## ADR-019 — `arch` cost-ranking is a first-pass ranker, not an oracle — verify every non-trivial move
**Decision:** the `arch` critique was made cost-aware — each dir carries `~N to move` (weighted count of import statements that rewrite on relocation) and the LLM ranks findings by impact/cost. This turned it from a smell list into a usable refactor backlog, and its cheap wins were acted on: `config.ts`, `git.ts`, the six single-command backends (arch/search/skill/spec/plan/ship), `a11y`, `docs`, `integrations/ado`, `doctor` — all consolidated (`src/` 33 → 21 top-level dirs, 0 cycles throughout). But the cost signal is a **weighted import-edge count and nothing more**, so it is blind to four things a human must check before executing any move it proposes — each proven by a finding it got wrong this cycle:
- **Cycles.** It scored `server → observe` at ~4 (the raw edge) but missed that server also imports `loop/{observe,events,transcript}`, `loop/engine` produces those events, and both share `loop/types.ts` — so any merge creates an `observe ↔ loop` cycle. A clean move needs the event *types* extracted to a neutral module + edits to the loop core; not a ~4 merge. Left as-is (the producer/consumer coupling is real architecture).
- **Coverage-config semantics.** It first suggested `integrations/ado` → `cli/`, but `cli/**` is coverage-excluded ("argv glue"); folding a 258-line *tested* module there would mislabel it and hide its coverage. Only once `commands/` existed (coverage-included) was there a clean home. The metric counts imports, not vitest excludes.
- **Importer accuracy.** It claimed `util/json.ts` had "2 importers, both `review/`" → move it there. Ground truth was **three** — `brain/claude-code.ts` also imports `extractJsonStrict`. It is a genuine shared util; moving it inverts a `brain → review` dependency. The cost number is only as good as the graph, and the graph undercounted.
- **Type/format sharing.** The `server → observe` tangle again: an event *format* shared between a producer and a consumer reads as two cheap edges but is one inseparable seam.

**Why:** record it so the next person (or agent) treats `arch` output as a *ranked hypothesis list*, not a work order. Cheap-looking moves (`~1`–`~2`) are usually safe and were done wholesale; anything touching a hub, a cross-layer edge, or the loop core gets a `git grep` of real importers + a cycle/coverage check first. The improved-then-bounded tool is the point: cost-ranking makes the backlog tractable, human verification keeps it correct. Division of labor that held all cycle: the LLM (ollama `arch`) ranks by cost; a human/bridge brain verifies and executes — the ollama *coder* brain, by contrast, could not drive these edits at all (it stalled on `max_steps`/`difficulty`), so "use the loop" means use it for analysis, not autonomous mechanical refactors.

## ADR-018 — Gate the gaps a human caught, not a check
**Decision:** three gates added after a retrospective on what shipped past green CI this cycle. (1) **dist smoke-run** ([`scripts/smoke-dist.mjs`](../../scripts/smoke-dist.mjs)) — after the build, actually *run* a dist CLI to completion and import the whole TUI module graph; wired right after `dist build`. (2) **UI perf budgets** ([`scripts/bench-ui.mjs`](../../scripts/bench-ui.mjs)) — assert the diff-flush emits ≤3% of a full repaint on a 1-cell change and `control.html` ≤80 kB (both machine-independent), plus coarse ~×80-margin timing backstops. (3) **full-catalog parity + snapshot** — every one of the 44 widgets rendered in both backends and snapshotted, not just the two that had tests. **Why:** each closed a gap that a *person*, not a gate, had caught. The `dist build` step only proved dist *compiled* — it never ran it, so an unrunnable dist (bare `@facet/*` imports resolving to extensionless TS source) reached a user as `probevane tui` `ERR_MODULE_NOT_FOUND`; the smoke gate reproduces and catches exactly that. The gauge egg-shape, a garbled stepper, and SVG typography were all found by *eyeball* on a screenshot — the snapshot gate turns those into diffs. No UI perf was ever measured, only designed for — the perf gate makes the diff-flush's flicker-free promise a number that fails when broken. Verified each fails when its budget is exceeded and passes restored, same as any test. The rule the cycle re-taught: a gate that never executes the artifact (compile-only, eyeball-only, unmeasured) is not a gate.

## ADR-017 — Vendor the drawing engine in-repo; ship one self-contained package
**Decision:** move the facet engine from a sibling repo (`file:../facet/packages/*`) into probevane as internal npm-workspace packages under [`engine/*`](../../engine); deps become `@facet/*: "*"` (resolved to the workspace, `node_modules/@facet/*` symlinks `engine/*`). Imports stay `@facet/*` everywhere — nothing in `src/` changed. The published `dist/` esbuild-bundles each package to `dist/node_modules/@facet/*` so plain node runs it (node resolves that copy nearer than the repo's node_modules); `npm pack` includes it and an extracted tarball resolves it. **Why:** a `file:` dep on a sibling repo means a lone probevane checkout can't `npm install` — probevane grades *other* people's repos, so it must itself be one thing you can clone and build. Vendoring keeps the clean package boundary (the engine is still `@facet/*`, its 228 tests + parity/snapshot/lint gates came intact) while making probevane self-contained and publishable as **one** package. The old standalone facet repo was tar-archived (history preserved), not deleted. The bundling-to-`dist/node_modules` trick is what makes the TypeScript-source engine runnable under plain node without a per-package build — verified physically in the tarball and by importing the extracted dist.

## ADR-016 — One vector Painter, two backends (the drawing engine)
**Decision:** extract all shared drawing into **facet** — an abstract immediate-mode `Painter` (`rect/line/polyline/polygon/arc/text/push/pop` + a `caps` capability record) with two backends: `CellPainter` (terminal — box-drawing for axis-aligned, **braille** 2×4 subpixels for curves/diagonals) and `SvgPainter` (browser — a DOM-free SVG string). Every widget is authored **once** against `Painter`; a widget may branch on `caps` only where a medium genuinely cannot follow, and those branches are few and documented. Where a shape reads differently per medium but the widget shouldn't know (a circle is round in square SVG pixels, an egg in 1:2 cells), the **backend** compensates — `CellPainter.arc` squashes the vertical radius so gauges/donuts read round in the terminal while SVG stays round, with the widget none the wiser. **Why:** the control center is rendered twice, and hand-writing each widget per medium meant every visual (gauges, constellation edges, panel backgrounds) was built and bug-fixed twice and drifted. The model was *already* shared (packed-colour `Style`, `layoutDag`, the constellation builder); only the drawing was duplicated. A `Painter` seam collapses authoring to one surface without flattening either medium — SVG keeps crisp vectors, the terminal keeps hand-tuned box-drawing and *gains* braille curves it never had. The go/no-go was a side-by-side catalog: cell fidelity had to meet or beat the old hand-tuned TUI before the duplicated draw code was deleted. See [Drawing Engine](Drawing-Engine.md).

## ADR-015 — Control-center UI: convention-resolved TSX, generated artifact, runtime compiler
**Decision:** the dashboard is TSX components with **no framework** (a 40-line `h()` runtime building real DOM; text children via `createTextNode`) and **no hand-written component imports** — a capitalized tag resolves to `src/ui/app/components/<Name>.tsx` by convention; the esbuild plugin injects the import, a missing file is a compile error, filename = exported name is enforced, and a local `h`/`Fragment` fails the build (lexical shadowing of the JSX factory crashed a component silently before the guard). The served `control.html` stays a **generated single self-contained file** (drift-gated like SKILL.md); under `PROBEVANE_UI_DEV` the daemon recompiles the sources per request (~20ms), which is what makes the design loop's rewrites live. The design loop itself gained a **selector-preservation gate**: a CSS rewrite that drops any selector is reverted, not applied — the LoRA lesson again (instructions requested ≠ contracts bound; a local vision model dropped 66 selectors in one rewrite). **Why:** component structure + compile-time-findable imports without adopting a framework or shipping runtime deps; every existing invariant (single-file serving, XSS-by-structure, CI drift gates, quality bar scanning the sources) kept its teeth — the quality gate flagged the UI's own first draft three times.

## ADR-014 — Mutation gate hardening: floor 0.5→0.6, process-group kill
**Decision:** raise the CI self-mutation floor (`mutation . --budget 60 --min-score`) from 0.5 to **0.6**, and make `sh()` timeouts kill the whole **process group** (spawn detached, `kill(-pid)`, 2s fallback resolve with code 124). **Why:** the floor was set before it was ever measured; two measured runs on 2026-07-02 scored **1.0** (60/60) and **0.8** (48/60 — the sampler hit fresh code: doctor checks, a11y rules, the python adapter's new venv branch), so 0.5 let half the sampled mutants survive without failing CI. 0.6 keeps ≥0.15 headroom below the worst measured run (never set the floor above measured−0.05; sampling varies with tree state and runner speed). The group-kill exists because measurement itself exposed the bug: a mutant-induced infinite loop orphaned vitest workers past the 3-minute timeout — bash died, the workers kept the stdio pipes open, `close` never fired, and the run hung 3.5h. Every gate shells through `sh()`, so one fix closes the hang class loop-wide. Honest note: the 0.8 run's 12 survivors live in the newest code — strengthening those tests is queued work, not a reason to lower the floor.

## ADR-013 — Quality analyzer: AST function detection + literal-robust metrics
**Decision:** detect functions via the ts-morph **AST** (each function measured on its own body, nested functions are separate nodes), and run the line-based metrics (long lines, imports, debt, duplication) over a **literal-aware strip** that removes comments and collapses strings / regex / single- and multi-line / nested template literals. Long-line width is measured on the *stripped* line; duplication compares string *content* and skips import blocks; debt only counts a leading or colon-suffixed marker. **Why:** the original line-based brace-matcher couldn't tell a nested closure from a block (it absorbed callbacks into the parent, inflating cognitive/nesting and hiding the nested function), and counting literal text produced a parade of false positives — a `{` inside a regex, control-flow words inside a template, a 46-row command table read as 41× "duplication", import headers flagged as dup, the analyzer's own `TODO/FIXME` docs flagged as debt. probevane grades *other* projects (template- and data-heavy frontends are first-class), so the gate has to measure real complexity, not surface text. All eight false-positive classes are closed; the analyzer holds its own 100/100 self-grade. See [Runes & Gates](Runes-and-Gates.md).

## ADR-012 — Isolate (self-)improvement in a worktree; review before merge
**Decision:** `--worktree` runs a path loop in a throwaway git worktree on its own branch (live tree untouched until an explicit merge); it symlinks every `node_modules` (root + nested) in, commits only `outcome.editedFiles` on accept (never `git add -A`), and self-reviews the committed diff — `--worktree-merge` blocks the auto-merge on any review `error`. The $0 bridge servicer is a first-class agent (`probevane-brain`) whose discipline is to adapt to gate feedback. **Why:** refactoring probevane *in place* while the loop runs on it is self-modifying risk, and a green suite can't catch a dropped case — so isolation + a review gate make self-improvement safe and give a clean before/after. The `-A` ban is hard-won: an early hand-run committed the worktree's `node_modules` symlink and clobbered real deps on merge. A *deterministic* servicer can't react to gate feedback and stalls, so adaptiveness is the agent's core rule. See [Worktree mode](Worktree.md).

## ADR-011 — On a real app, validate only the tests we wrote
**Decision:** `validation_gate`/`acceptance_gate` run scoped to the new spec files (`run(dir, scope, files)`), and `validation_gate` relaxes typecheck if the project didn't typecheck cleanly at baseline. `discover` ranks targets by testability; the MSW setup patch preserves the jest-dom import. **Why:** real apps ship their own (often jest-era, env-incompatible) tests and may not typecheck under our config — none of that is ours to fix when *adding* tests. Whole-suite-green would make acceptance impossible; scoping to our specs makes "did we add good tests?" the real question. Proven: 22 passing tests generated on a production app's redux slices.

## ADR-010 — Mock the boundary; chain contracts along the graph
**Decision:** a deterministic mock maker (`src/mock/`) synthesizes a module's input boundary (network→MSW from OpenAPI/types, dep `vi.mock`, prop fixtures, fake time), starts MSW globally so specs need only async waiting, and threads each module's captured output as the next module's input fixture (single `test-fixtures/*.json` source of truth). **Why:** real apps are multi-module + networked — you can't test a component without faking its inputs, and re-mocking each module independently drifts. Capturing the upstream's frozen output and asserting it downstream keeps the chain coherent. `hermetic_gate` enforces the mocks are actually used.

## ADR-009 — Cache the stable prefix; cap + prune the rest
**Decision:** mark the system+tools prefix `cache_control: ephemeral`; cap command output (head+tail) and prune tool-result bodies older than 8 turns. **Why:** the system block (base + runes + RAG + tools) repeats every turn and dominated input tokens. Caching it cut billed input ~40% with zero behavior change; capping/pruning bounds the growing transcript.

## ADR-008 — path_guard: deps live inside the project
**Decision:** a `path_guard` rune denies writes/deletes to `node_modules`, build dirs, and lockfiles; it's first in the `write_tests` pipeline. **Why:** `tools.ts` blocks absolute paths and `..` escapes, but `node_modules` is *inside* the project dir, so those guards let it through. A real run proved the risk — a model stuck on a typecheck failure "fixed" it by overwriting `node_modules/.bin/tsc`, corrupting the toolchain. The scope a model can damage must be fenced explicitly.

## ADR-007 — Stack-knowledge belongs in the adapter, not the core
**Decision:** spec-file discovery, generation guidance, and test patterns are adapter methods (`specFiles`/`guidance`/`patternsDoc`), not core constants. **Why:** adding the python stack revealed these were implicitly JS/React in the core (the `*.spec.ts` regex, the vitest placement string, `unit-patterns.md`). Pushing them behind the contract kept the loop/gates/scorer/library stack-agnostic; the python adapter then dropped in and a 3rd stack needs zero core edits. The modularity test exists precisely to surface this kind of hidden coupling.

## ADR-006 — Stop-to-validate needs a nudge + a delete tool
**Decision:** give the brain a `delete_file` tool and, when `barren` hits the ceiling, inject one nudge telling it to finish (stop calling tools) or clean up — before giving up. **Why:** `validation_gate` is a `shouldStop` gate, so it only runs when the model *attempts to finish*. A model that keeps tinkering never triggers the feedback loop; it also stranded empty placeholder files it couldn't remove. The nudge converts blind tinkering into stop→validate→fix; the delete tool lets it clear leftovers. Observed: a 22-step/160k-token stuck run became 6 steps/27k tokens, 100% coverage.

## ADR-005 — Living wiki, served zero-dep
**Decision:** docs as markdown under `docs/wiki/`, served by a dependency-free node script (`scripts/wiki.mjs`, marked via CDN). **Why:** browseable without a build or extra deps; renders on GitHub too; updated every phase.

## ADR-004 — Anthropic SDK brain, Haiku default
**Decision:** default brain calls the native Anthropic Messages API with `claude-haiku-4-5-20251001`; retries on 429/529/5xx. **Why:** the loop depends on reliable per-turn tool calls, which the Max-plan `claude -p` path can't do; Haiku is fast/cheap and tool-capable. `claude-code` stays a possible alternate for review/takeover. **Risk:** bills API credits.

## ADR-003 — Tests are a gate, not a tool
**Decision:** the model gets read/list/write/edit/plan tools, but **not** a "run tests" tool; the suite is run by `validation_gate.shouldStop`. **Why:** "done" must mean "the whole suite is green now", not "a partial run looked green". Prevents the model from stopping early.

## ADR-002 — Port runestone's contract to TS, don't embed the binary
**Decision:** re-implement the Rune contract + loop in ~400 LOC TypeScript rather than embedding the Rust runestone. **Why:** the first-class targets (React/vitest/Playwright) and qaforge's proven test-gen logic are TS; a Rust core would force FFI/subprocess bridges and kill the reuse story. Runestone's value is its *shape*, which ports cleanly.

## ADR-001 — New unified harness, adapter-modular
**Decision:** build a new tool (not extend qaforge/qa-harness-template), with all stack-specifics behind a `StackAdapter`. React first; pytest stub proves drop-in. **Why:** user wants one transferable harness; the three assets overlap but none is the union. Modularity is the transferability mechanism.
